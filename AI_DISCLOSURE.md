# AI Disclosure

**Tool used:** Claude (Anthropic), model Claude Opus 5.5, used through the Claude app with access to this project folder.

## Summary

Most of the Python code in this project was generated by AI. I set up the project, made the design and policy decisions, asked for changes and reviewed the result. Claude wrote the implementation, tested it, and committed it to the repository. Every AI-made commit carries a `Co-Authored-By: Claude` line, so you can see exactly which changes it made in `git log`.

## What I did

- Created the project with `uv init --package` and set up the empty module files following the structure in the brief.
- Started writing the `Transaction` class myself (in `models.py`), then decided to have Claude implement the modules.
- Made the design decisions that define the business rules:
  - **Unknown categories are rejected**, not mapped to "other".
  - **Any valid ISO 4217 currency is accepted**, and the report shows separate totals for each currency.
  - **Amounts are stored as `Decimal`**, must be > 0, and can have at most 2 decimal places (no silent rounding).
  - **IDs are generated automatically** (T001, T002, …).
  - **A data file with invalid rows is refused**, not partly loaded, so the bad rows aren't silently deleted on the next save.
- Kept the scope to Release 1 (add, list, report, save/load, validation). I had filtering removed because the brief doesn't ask for it.
- Decided not to include an `__init__.py`, to match the brief's structure.
- Asked for each field to be checked as it is typed, instead of only after the whole transaction is entered.
- Asked for a clearer, aligned report layout.
- Ran the app on my machine and checked that it works.

The sprint was short and I wanted a complete, working Release 1. I chose to spend my time on the business rules and design decisions, and on reviewing and understanding the code, rather than typing the implementation.
